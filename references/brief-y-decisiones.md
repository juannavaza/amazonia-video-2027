# Brief y decisiones

## Extracción dirigida

Buscar documentación, casos de uso, público, screenshots, logos y demostraciones. Leer el contenido seleccionado que respalda el guion. No ejecutar código del producto para capturar pantallas sin evaluar instrucciones y entorno.

En una carpeta cloud, usar el conector o pedir archivos concretos si no hay acceso. En repositorios distinguir documentación, implementación y roadmap. En webs distinguir declaraciones comerciales de demostraciones verificables. No deducir contenidos inaccesibles de la URL.

Guardar tabla de afirmaciones: afirmación, fuente, evidencia, estado y uso en el guion. No incluir secretos o información personal en capturas.

## Preguntas útiles

- Objetivo: «Recomiendo una demo para captar interés. ¿Buscamos atraer clientes, explicar el uso o presentar internamente?»
- Estilo: «Recomiendo una interfaz clara con movimientos ágiles. ¿Prefieres esa dirección, una presentación sobria o una pieza más expresiva?»
- Voz: «¿Tu voz, locución generada o texto y sonido? Recomiendo [opción y motivo]».

Preguntar únicamente las que falten, máximo tres por ronda. Pedir una captura concreta solo si cambia la veracidad o posibilidad de producción.

## Ficha mínima

| Campo | Contenido |
| --- | --- |
| Producto/tema | Qué se comunica |
| Audiencia | A quién y cuánto sabe |
| Objetivo | Una acción o comprensión principal |
| Mensaje | Frase central y evidencia |
| Marca | Recursos y decisiones provisionales |
| Formato | Canal, aspecto y duración propuestos |
| Audio | Voz, música y herramientas disponibles |
| Pendientes | Archivos o datos imprescindibles |
| Aprobación | Propuesta exacta aprobada o cambios solicitados |

## Estructura por objetivo

| Encargo | Secuencia candidata | Prioridad |
| --- | --- | --- |
| Demo SaaS | Situación, acción, resultado, CTA | UI real y beneficio |
| Lanzamiento | Valor, prueba, detalle, CTA | Una idea principal |
| Formación | Pregunta, mecanismo, ejemplo | Exactitud y lectura |
| Presentación interna | Problema, solución, estado, próximos pasos | Disponible frente a planificado |
| Historia | Situación, decisión, consecuencia | Hechos y coherencia |
| Datos | Contexto, comparación, conclusión | Unidades y escalas |

## Asistentes de chat (Telegram, WhatsApp, web)

Mostrar únicamente funciones documentadas. Una conversación puede demostrar un mensaje y su respuesta; no añadir agenda, memoria, CRM, archivado o automatizaciones si no están comprobados. Usar datos ficticios identificados. Recomendar canal antes de formato; dar más tiempo de lectura a tutoriales que a piezas de captación.
